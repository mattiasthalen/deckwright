# Evals

The eval suite of the `deckwright` plugin, run with Claude Code's own runner, [`claude plugin eval`](https://code.claude.com/docs/en/plugin-evals). It lives at the repo root rather than inside the plugin, so it never ships with it: the marketplace installs `./plugins/deckwright` and nothing outside it. Each case names the plugin itself, with `plugins: ["../../plugins/deckwright"]` in its frontmatter.

The script's computable parts are checked by the unit tests in [`tests/`](../tests/README.md). These cases check the skill's side: what it asks, says, suggests and records, and that it goes through the script to do it.

## Terms

- **Case**: a directory here with a `prompt.md` and `graders/`. **Run**: one agent session on one case.
- **Scripted player**: each prompt is the player's opening message followed by the player's whole side of the conversation, written in advance, with an instruction to play it through. A run is one turn: the agent asks, takes the answer from the script, and carries on. The four scripted cases also carry the same `append_system_prompt` in their frontmatter: the player's whole side is already in the first message, the agent says and asks everything it would to a live player but takes each reply from the script instead of ending its turn, it ends its turn only after the script's last line that applies, and it does not write the player's lines out. It is there because runs ended early: in the first `--runs 8` pass, 6 of 24 network runs ended after 4 or 5 turns with no `deck.py` call, and kept probes ended mid-script right after a question to the player, or after writing the player's answer out themselves. It is scaffolding only and says nothing about what the skill should do. With it, 1 of 32 network runs has ended early since (the `--runs 8` judge passes of `build-a-deck`, `bend-the-template` and `card-traps` on its current wording), against 1 of 6 under a first wording that told the agent to carry on "as if you had just received" each reply. In the re-plan traces of the four collection-era cases (32 runs, 2026-11-08), 3 ended early, all in the longer scripts (`collection-rats` run 8, `theme-conflict` runs 6 and 7), each right after writing a player's line out. That wording also had one run record a card it should have asked about first, so the prompt now says to ask everything a live player would be asked. Runs still write the player's lines out, about one echo per message, despite the instruction; the graders allow for it (see Known limits).
- **Trace**: the run's session log, one JSON message per line. Most graders read it, the deck page the run leaves behind (`decks/<file name>.html`, named after the deck; `decks/meren-of-clan-nel-toth.html` for a deck the player gives no name, which the skill names after its commander), or both.
- **Grader names** start with the name the spec gives the check (`bracket-push-flagged`). Where one check needs more than one grader, the others add a suffix after `--` (`bracket-push-flagged--on-page`). A check passes on a run when every grader under its name passes. `skill-fired` and `looks-up-before-describing--only-through-the-script` are preconditions without a spec id: a run in which the skill never loaded, or which fetched card facts round the script, says nothing about the checks.

## Run

From the repo root. `--allow-tools` applies to every case in a run, and the cases need different network and shell grants, so each tag has its own command.

### On a Linux host such as a cloud container

The run's OS sandbox needs `bubblewrap` and `socat` (`apt-get install -y bubblewrap socat`), and `TMPDIR` must point at a folder outside `/tmp`:

```sh
mkdir -p ~/evaltmp && TMPDIR=~/evaltmp claude plugin eval . …
```

Each run's own settings deny writes to `//tmp`, and the runner makes the run's workspace under `TMPDIR`; left at `/tmp`, the workspace is read-only to Bash, `deck.py` cannot write `deck.json` or the page, and every case but `no-code-execution` fails.

| What | Arguments after `claude plugin eval . --model claude-opus-5 --judge-model claude-opus-5 --ablation none` |
|---|---|
| `build-a-deck`, `bend-the-template`, `card-traps`, `collection-rats`, `theme-ideas`, `theme-conflict`, `not-owned-declined`, and S4's `review-a-deck`, `review-with-collection`, `fantasy-deck`, `ninety-nine`, `review-a-deck-picked-up` (Scryfall reachable). The five S4 cases also carry the tag `review`: `--tag review` in place of `--tag network` runs only them | `--tag network --scaffold --allow-tools Bash Write Edit "WebFetch(domain:api.scryfall.com)"` |
| `lookup-unavailable` (Scryfall blocked) | `--tag offline --scaffold --allow-tools Bash Write Edit` |
| `no-code-execution` (no shell) | `--tag no-bash` |
| One case, once, while iterating | its tag's arguments with `--case <name> --runs 1` in place of `--tag` |
| While working | its tag's arguments with `--runs 3` |
| Judging a change | its tag's arguments with `--runs 8 --json result.json` |

Add `--trust-plugin` when the run cannot stop to ask, such as under `--json` or in CI. Add `-j 8` to run eight at once; drop to `-j 4` if runs report Scryfall's rate limit (429).

Why the grants differ:

- **Network.** A shell command runs under the run's OS sandbox, which reaches only the domains granted with `WebFetch(domain:…)`. The `network` cases keep `api.scryfall.com`, where the script asks for the bulk file's address once its copy is a week old. The skill looks up every card it suggests and nobody can know those cards in advance, but the scaffold's copy of the bulk file answers them, so a run reaches neither Scryfall host unless that copy is stale; `data.scryfall.io` is not granted. Each case's scaffold also pre-fills the per-card cache (`deckwright-cache/`, laid out as [`tests/README.md`](../tests/README.md) fixes) with every card the scripted player names, so the cards the graders depend on never wait on the network. The same grant would let the agent call WebFetch itself, which is why those cases carry `looks-up-before-describing--only-through-the-script`. Every lookup but the per-card cache's is read from Scryfall's Default Cards bulk file (`deckwright-cache/default-cards.jsonl.gz`). A run would download its 81 MB each time, so each scaffold copies it from one copy kept on the host by [`tools/bulk-cache.sh`](tools/bulk-cache.sh), under `$DECKWRIGHT_EVALS_CACHE` (default `~/.cache/deckwright-evals`), fetched once and again when it is a week old; the first run of a day can wait a minute on it. `lookup-unavailable` gets none. The collection cases carry the player's ManaBox export as `ManaBox_Collection.csv`: rows cut from a real export with every `Purchase price` blank.
- **Offline.** `lookup-unavailable` is run without the grant, so the script cannot reach Scryfall. Its cache holds only the commander, since a deck cannot be started without one.
- **No shell.** `no-code-execution` is run with no `Bash` grant, which is how a Claude Code session looks without code execution.

### Pinned settings

| Setting | Value | Why |
|---|---|---|
| `--model` | `claude-opus-5` | Whether a skill triggers depends on the model, so it is pinned and a model rollout is not read as a plugin regression. |
| `--judge-model` | `claude-opus-5` | The default judge is a small fast model; several rubrics here ask what a critique said and why. |
| `--ablation` | `none` | Without the plugin there is no script and no template, so a baseline arm scores 0 by construction and doubles the cost. |
| `--runs` | 1 while iterating, 3 while working, 8 to judge | The spec judges each eval check at `--runs 8`: it passes when it passes every run. |
| `--max-cost-usd` | none | Runs are bounded by each case's `max_turns` and `timeout_seconds`. |

## Reading a result

Results land in `evals/results/<timestamp>/`, which `evals/.gitignore` keeps out of git. Pass `--json result.json` for one file, and `--keep-temp` to keep each run's workspace and trace.

1. **Check for errors first.** A run that hit a usage or rate limit, a turn cap or the timeout usually scores 0 for reasons that are not the plugin's.
2. **Don't go by the exit code.** Compare each case with its Now in the [Cases](#cases) table.
3. **Read a failing run's trace before believing it.** A grader that did not expect how a correct run phrased something fails a correct run; fix the grader, not the skill.
4. **Run again, and count apart, a run that did not finish.** A run with no result line in its trace, or one that ends its turn at a question the scripted player has an answer for, is not graded: run it again, and report it beside the result as a run that did not finish, never as a pass or a fail. On the S4 prove runs (2026-11-09) such runs failed every grader past the point where they stopped (`U00nnJ` in `ninety-nine` ended its turn before the deck was full).

### Known limits of the graders

- **An `llm` grader with `focus: trace` cannot judge an interview, so none is used.** Measured on the first runs (2026-11-07): the judge gets the trace's first 12 and last 12 lines, and the trace is mostly streaming fragments. A `build-a-deck` run is 813 lines, 670 of them `content_block_delta`; both ends are the init line, deltas and the result line, so no assistant message from the interview reached the judge, and all ten such graders failed 3 of 3 votes on runs whose behaviour was correct. Every check they held is now decided by `regex` over the assistant messages, beside the `tool_used` and page graders it already had. The `llm` graders left judge what a run leaves in one piece: `no-code-execution` and `picked-up-offers-nothing` the last message, which a run of one reply fills, and S4's tribunal the deck file (see [The number check and the tribunal](#the-number-check-and-the-tribunal)).
- **The judgement checks are read by wording.** `starts-with-commander`, `walks-template-in-order`, `suggests-per-category`, `critiques-named-card`, `wrong-category-called-out`, `asks-for-collection`, `illegal-commander`, `unknown-card`, `bracket-push-flagged`, `lookup-unavailable` and `player-bends-the-template--says-what-changed` each require every part of the criterion in one assistant message, near the card or category it is about, and each part as one of a set of phrasings: the purpose from `counts_when`, "taps for {C}{C}", "makes no mana", a ManaBox CSV export asked for, "not legendary", a question mark where the criterion says *asks*. Each grader's comment says what it requires and in what window. The sets are taken from four real runs and widened beyond them, but a correct run that says it some other way fails, which is stricter than the criterion; read such a failure in the trace and widen the set, never the window. A list of suggestions passes `suggests-per-category` when two of its items carry a line of 15 characters or more after the name: the grader sees that each says something, not that it is true.
- **A run plays both sides in one message**, echoing the player's answers ("You said: card advantage", "(Taking your answer: …)"). A window that runs past the question handing the choice back would read the player's words as the assistant's, so the windows of `wrong-category-called-out` stop at the first question mark after the card, and `lookup-unavailable--nothing-said-before-the-text` stops at the question asking for the text. The `looks-up-before-describing--<card>` graders do not count a mention inside an echo: on a quoted line (`> *"Add Sign in Blood as ramp."*`), inside "(Taking your answer: …)" or "(Your answer: …)", the quoted answer included (`*(Taking your answer: "Meren of Clan Nel Toth.")*`), or straight after "You said:". A description written into the same line after the echo is not seen.
- **Order in the trace is read by pattern.** `looks-up-before-describing--<card>` fails when an assistant message names the card before any `deck.py` lookup of it, except a message that says it is looking, checking or fetching. A mention that is not a description, such as "Meren, good choice", fails it too, which is stricter than the criterion. Read such a failure in the trace.
- **A tally counts only as a Bash call of its own.** `tally-after-category--after-lands` and `--after-ramp` want `tally` in a later Bash call than the `add` before it, as the skill tells it to run; a run that chains `add … && tally` in one command fails them though the tally ran. `tally-after-category--no-count-before-a-tally` and `player-bends-the-template--later-tally-uses-it` count `new` and `add` as tally runs too, since both print the tally: a run that shows Lands at 0 / 38 straight after `new` is showing the script's count.
- **The trace patterns assume Claude Code's session JSON**: compact, a tool call as `"name":"Bash","input":{"command":"…"`, an assistant message carrying `"role":"assistant"` before its content, text blocks as `"type":"text","text":"…"`. The trace carries every text twice, once as that `assistant` line and once as stream deltas; the patterns anchor on the `assistant` line. A line break inside a text is the two characters `\n`, so `\b` does not hold before a word that starts a line (`\nKeep` has no boundary); the patterns write a word start as `(?:\b|(?<=\\n))`. If the runner's trace changes, every trace grader fails at once; that is the first thing to check.
- **The runner's regexes run on JavaScriptCore, which gives up where V8 does not.** `claude` is a Bun binary, and a regex that backtracks past JavaScriptCore's limit reports no match rather than an error. So a `contains` grader fails a run that has the match, and a `not_contains` grader passes a run that has it. Measured on the final `build-a-deck` pass (2026-11-07): `starts-with-commander` failed 6 of 8 runs in the runner and passed all 8 under node. Each lazy walk of the form `(?:(?!guard)[\s\S])*?` takes one step per character. Before the commander question, the six failing runs had 10,900 to 12,300 characters on assistant lines, where the guard is tried at every character, against 9,400 to 9,500 in the two that passed. The six were also the runs whose Skill call carried `"args":"commander deck"`; nothing else about them differed. The generated walks now pass a whole trace line in one step when the line holds neither `"name":"Bash"` nor `"role":"assistant"`, the two places every guard and every pattern after a walk can start. A line is passed either whole or one character at a time, never both, or a failing match would retry every split. On every kept trace, and on each final-pass trace repeated four times, Bun and node now agree on every regex grader. [`tools/grade-trace.mjs`](tools/grade-trace.mjs) runs itself under `bun` when it can and marks `ENGINES DIFFER` on any grader where V8 disagrees: such a grader is near the limit and needs a cheaper pattern.
- **The page is read at `decks/<file name>.html`** in the working folder (`decks/meren-of-clan-nel-toth.html` in the S1 cases, `decks/trash-pandas.html` in `theme-conflict`), where [`tests/README.md`](../tests/README.md) says the skill renders it in Claude Code, and by the `data-section` and `data-category` marks the unit tests also hold the page to.
- **`only-the-player-chooses--first-declined` reads the declined card from the first offer.** The first offer's card differs from run to run (Yavimaya Elder, Wood Elves, Farhaven Elf, Kodama's Reach on the S4 prove runs), so the grader cannot name it: it takes the card from each of the first ten `swap` or `maybeboard add` commands of the run and fails when that card was named in the first offering message, before its first question. Until 2026-11-09 it looked between the first offering message and the next for any such command, and failed 14 runs that took the player's no and recorded swap 2 in that window. Two prove runs still fail it, and are read as failures: `Ze4YW9` put the declined Yavimaya Elder on the maybeboard later, and `t8Q9jh` swapped the declined Farhaven Elf in for Mulch. A basic land is not taken, since its name is a word of ordinary prose.
- **`review-covers-the-whole` judges a long file.** The deck file it reads is about 55 KB (54,482 to 60,893 bytes on the first runs), and the runner notes on every such verdict: "long file (55804 chars); llm judges are noisy on long inputs, prefer a regex grader for large artifacts". The same note is on each file-judged tribunal grader. Their calibration pairs (below) measure that noise; read a split vote as noise before believing it.
- **The number check needs the run's trace to see earlier measures.** A review written again after swaps that compares with the first review ("down from 58 pips", "Plan came down from 40") cites a number only the first measures printed. Without the trace, `review-numbers.mjs` reports it as stray: on the S4 prove runs (2026-11-09), `7nZOxA` gave `58 16 40` and `yE4k9z` gave `40`. Given the trace, it carries every number a `deck.py` command printed during the run, and every kept review run checks clean. A number the script printed for any reason is carried, so the trace widens what passes; read a review that cites an old number as old.

## The number check and the tribunal

Two of S4's checks are not run by `claude plugin eval` alone.

**The number check (AC22)** is [`tools/review-numbers.mjs`](tools/review-numbers.mjs). It holds each number in a written review to what the script printed. Run the review cases with `--keep-temp`, then for each kept run save the run's tally and check the run's deck file against it. From the run's working folder (`<workspace>/home/cwd`), with the deck file the case names:

```sh
uv run <repo>/plugins/deckwright/skills/interview/deck.py tally --deck decks/meren-recursion.json > ../tally.json
node <repo>/evals/tools/review-numbers.mjs decks/meren-recursion.json ../tally.json <workspace>/out/trace.jsonl
```

`tally` never touches the network and reads the run's own `deckwright-cache/`. The check first takes out every card name the deck file holds, and turn spans ("turns 4–6", "turns 7+", "turns 7 and on"). It then takes each number left in `review.text` and looks for it anywhere in `review.measures`, the tally, each card's copies in the deck file (`cards[].count`, so "25 Forests" is carried) and, when the trace is given, the output of every `deck.py` command the run made. The trace is optional, and without it a number from an earlier measure is reported (see [Known limits](#known-limits-of-the-graders)). A single "turn 8" is a number like any other. It exits 0 when every number is carried, and 1 when some are not, printing each such number on a line of its own. It exits 2 when the deck file has no written review, or the deck file, tally or trace cannot be read. Its unit tests are in [`tests/test_evals_tools.py`](../tests/test_evals_tools.py).

**The tribunal** is the `llm` graders that judge the deck file a run leaves, not the trace: `review-covers-the-whole` (AC23), `fetch-lands-named` (AC24), `swaps-explained-and-ordered` (AC27) and `no-stale-finding` (AC32), in `review-a-deck` and `review-with-collection`. Each reads `focus: { source: file, path: decks/meren-recursion.json }`. A probe on 2026-11-09 showed the runner accepts that key. The runner takes three judge votes per grader, and two passes is a pass. Each rubric describes the deck file's keys, gives the deck's starting counts and the cards counted on a stretch, and judges one thing. `picked-up-offers-nothing` (E17) is judged the same way, on the one reply (`focus: last_message`).

## Judge calibration

Each `llm` grader gets one known pass and one known fail in `evals-calibration/<grader>--<pass|fail>-<n>/`, built from real run outputs: the pass a real output judged by hand, the fail the same output with one passage changed. The bar is agreement of at least 0.9 and no flips; a grader below it is reworded or replaced by a deterministic one.

`no-code-execution`. Its pair is a real reply from the final pass (2026-11-07, run nPsbm6), judged a pass by hand: it says the interview needs code execution, says how to turn it on in Claude Code and in the Claude app, and starts nothing. The fail is the same reply with its last sentence replaced by "While you do that, let's start: who's your commander, and what bracket are you aiming for?". Each calibration case has the agent repeat its reply word for word, and grades it with a copy of the case's grader (keep the two identical) plus `reply-is-the-sample`, a regex that checks the judge read that text. Measured at 5 runs each with `--judge-model claude-opus-5` (2026-11-07, $1.05 in all): 15 of 15 votes PASS on the pass and 15 of 15 FAIL on the fail. That is agreement 1.0 and no flips, and every reply was the sample.

```sh
TMPDIR=/home/user/evaltmp claude plugin eval . --eval-dir evals-calibration --model claude-opus-5 --judge-model claude-opus-5 --ablation none --runs 5 --trust-plugin --no-publish -j 4
```

The run exits 1 because the fail case fails, as it should. Read each case's judge votes.

It gives the runner's verdicts when `bun` is on the PATH (or named by `$BUN`); without it, it warns that V8's verdicts can pass what the runner fails.

## Cases

**Now** is what the case does on the current text of the skill: runs that passed every grader out of runs made, and the known noise to read a drop against. When a change is judged, replace the case's Now.

| Case | Checks | Now |
|---|---|---|
